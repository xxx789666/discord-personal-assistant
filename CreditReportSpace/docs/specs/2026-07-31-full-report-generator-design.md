# 徵信報告半自動產製器 — 設計規格（v1）

日期：2026-07-31
狀態：設計定案，待實作
範圍：CreditReportSpace

## 1. 目標與定位

把現有「只產陸段（金融借款）」的工具，擴成能產出**整份九大段徵信報告骨架**的
半自動產製器：能從案件資料自動推導的段落自動填入，其餘段落保留範例版型的空白
表格與標題，交人工補齊。

一份報告 = 一個案件。每餵入一種資料，就辨識類型、填入對應段落、重新輸出目前
累積到的整份 DOCX。

### 非目標（明確不做）
- 外部查詢（商業司公司登記、動保設定、法學網、票信）→ 對應段落留空。
- 玖 優缺點分析、參 股東結構 → 留空（需人工判斷或外部資料）。
- 不臆造：抽不到／對不上／缺件一律標 `needs_review` 並回報，不靜默留空、不猜。

## 2. 首版（v1）範圍

三段，皆已用黃金案（去識別化代稱）實地逐格驗證：

| 段 | 來源 | 驗證狀態 |
|---|---|---|
| 陸 金融借款（B1 主債 / B2 從債） | 聯徵憑證 PDF（加密） | 逐格 100% 命中 |
| 肆一 損益表 | 綜合損益表(明細)管理報表 **或** 結算申報書 | 2025、2024 逐格命中 |
| 捌 保證人基本欄 | 身分證正/反面 JPG | 四張已讀出姓名/生日/證號/地址 |

v2（首版驗證後）：資產負債表（明細→彙總會計對應）、401 表（掃描視讀＋缺件偵測）、
Discord helper（分類＋解密＋逐次累積上傳）。

## 3. 已確立的抽取規則（資料驗證得出）

1. **聯徵憑證解密**：密碼＝當事人身分證字號**後 6 碼**；身分證號可從身分證正面
   JPG 讀取，故不需人工輸入密碼。（已用黃金案兩位保證人實地驗證：身分證號後 6 碼即為密碼）
2. **陸段餘額**：照抄聯徵 B1/B2「未逾期餘額」表列原值，不自行加減。印表時點後的
   每日增減只寫備註。
3. **陸段彙總**：同一（銀行 + 主借款戶 + 科目）多列 → 加總成一列。
4. **損益表暫結年慣例**：標「暫結」的年度，稅後淨利用**稅前**數、所得稅欄留空；
   確定年度（結算申報書）正常扣稅（稅後 = 稅前 − 所得稅）。
5. **金額換算**：元 → 仟元四捨五入。以來源實算為準（範例偶有 ±1 手工誤差）。
6. **銀行行名/科目簡稱**：照 `AGENTS.md` 對照表（行名寫到含「銀行/商銀」的常用
   全稱，不留兩字簡稱；科目 中期擔保放款→中擔 等）。
7. **缺件偵測**：範例某欄需要的期別/報表若無對應來源檔，該處標 `needs_review`
   並在回覆列出缺哪一件（例：申戶某年度全年 401、申戶某年度損益缺件）。
8. **保證人數與排序（捌）**：身分證以「人」計——N 位保人＝N 份身分證（正反面
   算同一人），非以 JPG 張數計。排序上**申戶負責人排第一位（（1））**；申戶
   負責人＝其姓名出現在申戶（案名主體）財報／結算申報書「負責人」欄者。抽取層
   將該保人標 `principal: true`，填格引擎據此穩定排序（principal 優先）。

## 4. 架構（模板填格，方案 1）

```
案件資料（資料夾或 Discord 附件）
        │
        ▼
   ┌─────────┐   類型：聯徵 / 損益(管理報表) / 損益(結算申報書) / 身分證
   │  分類器  │──────────────────────────────────────────────┐
   └─────────┘                                                 │
        │ 路由                                                  │
        ▼                                                       │
 ┌──────────────┐  ┌──────────────┐  ┌──────────────┐          │
 │ 陸 抽取器     │  │ 肆損益 抽取器 │  │ 捌 抽取器     │  … 每段一支
 └──────────────┘  └──────────────┘  └──────────────┘          │
        │ 各吐該段結構化 JSON                                    │
        ▼                                                       │
 tmp/docs/cases/<案號>/sections/*.json  （逐次累積，狀態）        │
        │                                                       │
        ▼                                                       │
 ┌──────────────────────────────────────────────┐              │
 │ 填格引擎：空白模板 DOCX + 所有 sections → 整份 DOCX│◀────────────┘
 │  - 固定表（肆損益、捌基本欄）→ 寫進既有儲存格      │
 │  - 變動表（陸借款）→ 產列插入模板對應位置          │
 │  - 缺件/needs_review → 淡黃底 + 備註「（待人工確認）」│
 └──────────────────────────────────────────────┘
        │ 原子替換寫出
        ▼
 output/doc/<案名>_徵信報告.docx  +  回覆摘要（needs_review/缺件清單）
```

### 4.1 元件與邊界

- **空白模板 `templates/credit_report_blank.docx`**：由範例 DOCX 洗掉所有真實
  數值、保留 21 表結構與段落標題／固定標籤而來。無 PII，可進 repo。版面的唯一
  真實來源；B（版面貼近手工範例）由此自動達成。
- **分類器 `classifier.py`**：輸入檔案 → 類型。內容特徵優先、檔名為輔。
  - 聯徵：解密後含「當事人綜合信用報告」「表B1」。
  - 損益(管理報表)：含「綜合損益表」且為明細科目格式。
  - 損益(結算申報書)：含「損益及稅額計算表」「營利事業所得稅結算申報」。
  - 身分證：影像含「中華民國國民身分證」（視讀）或檔名含「身分證」。
- **抽取器 `extractors/<type>.py`**：一類一支，純函式，輸入檔案路徑 → 該段
  結構化 JSON（沿用/擴充現有 `schema/`）。抽取層允許判讀但不臆造。
- **填格引擎 `template_filler.py`**：以段標題錨定（find heading → 後續表格），
  非固定索引，才能容忍模板微調。固定表填格、陸段呼叫既有 `docx_builder` 產列。
- **案件狀態**：`tmp/docs/cases/<案號>/`，含 `intake/`（原始檔）、
  `sections/*.json`（累積結構化資料）、輸出 DOCX。案號＝Discord thread_id
  或本機資料夾名。逐次累積：每次重跑填格引擎吃全部 sections。
- **CLI `gen_full_report.py`**：
  - 本機：`python tools/gen_full_report.py <案件資料夾> [-o 輸出.docx]`
    走訪子夾、全部分類抽取、一次填出整份，並印 needs_review/缺件清單。

### 4.2 跨段相依：聯徵密碼

聯徵解密需身分證後 6 碼。分類器遇身分證先快取「姓名→身分證號」；聯徵抽取器解密
時查表取後 6 碼。若聯徵先到、身分證未到 → 其他段照填，陸段標「待身分證解密」，
不中斷整份產出。

## 5. 資料流：本機整夾（黃金案）

1. 指向資料夾 → 走訪子夾（401/、信用憑證/、綜合損益.資產負債表/、結算申報書/、
   申請人.保人身分證/）。
2. 逐檔分類；身分證先建立「姓名→證號」表。
3. 各抽取器產 section JSON（聯徵用後 6 碼解密）。
4. 填格引擎：空白模板 + 全部 sections → 整份 DOCX。
5. 印 needs_review／缺件清單（v1 預期會列：資負整段、401 整段、參股東、伍、
   柒、玖、申戶某年度損益缺件）。

## 6. 錯誤處理

- 未知類型 → 回報「無法辨識，請確認為聯徵/損益/身分證」，不填。
- 聯徵缺身分證 → 填其餘、陸段標待解密。
- 掃描檔無文字層（v1 損益不涉，v2 401 才處理）→ 標 needs_review。
- 抽取不確定（影像模糊、欄位缺）→ 該儲存格 needs_review 淡黃底 + 清單。
- 每次輸出：暫存檔寫入後 `os.replace` 原子替換，中途失敗不毀累積中的檔。

## 7. 測試

- **分類器**：v1 四類各認對；未知類型正確拒認。
- **抽取器**：以去識別化黃金案為基準。真實個資只留 `tmp/`，測試 fixture 用去識別化
  假資料（`fixtures/` 只放明示 TEST/虛構）。陸段預期值已驗；損益 2025/2024
  預期值已驗（見本案驗證紀錄）。
- **填格引擎**：去識別化 sections → DOCX，比對關鍵儲存格與版面（表頭、合計列、
  needs_review 淡黃底）。
- **整合**：整夾 → DOCX，比對陸/肆損益/捌 已驗證儲存格。

## 8. 檔案邊界

- 只寫 `CreditReportSpace/` 內；成品 `output/doc/`、中間檔 `tmp/docs/`、
  模板 `templates/`。
- 真實個資只落 `tmp/` 與 `output/doc/`；log、回覆引用、fixture、git 一律不得含
  真實姓名/證號/統編/報表編號/帳號。
- 不改 `openab/`（Discord helper 屬 v2）、`INDEX.md` 或其他 Space。

## 9. 交付分期

1. 空白模板 + 填格引擎 + 陸段接入（骨架打通）。
2. 肆損益抽取器（管理報表 + 結算申報書兩格式）。
3. 捌 身分證抽取器（基本欄）。
4. 本機 CLI 串起整條 + 缺件/needs_review 回報。
